# Higher, Advertisable Accuracy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fine-tune the bundled embedding model on Tablight's labelled pool (plus licence-clean public data if it helps), ship it if it beats bge-small by the accept rule, and produce an advertisable precision/coverage figure from a sealed benchmark scored once.

**Architecture:** A frozen synthetic benchmark is written first. Python scripts (not shipped) fine-tune BAAI/bge-small-en-v1.5 on the Mac GPU and export a Xenova-layout ONNX int8 model; the existing JS head trainer gains a calibration split so thresholds are set on rows the encoder never saw. A winning model ships under a new model id with pinned hashes and a re-embed migration.

**Tech Stack:** Python 3.12 + PyTorch (MPS) + sentence-transformers 5 + optimum/onnxruntime (scratch venv `ft-venv`); TypeScript, transformers.js, vitest, Playwright.

**Spec:** docs/superpowers/specs/2026-11-20-accuracy-design.md

## Global Constraints

- Title + URL only; never page content. No user tabs in training or test data.
- Never open rows of tests/quality/holdout*.json, youtube-messy.json, sessions.json, or tests/benchmark/benchmark.json (aggregates only). The benchmark is scored exactly once, in Task 7.
- Download stays ~34 MB; embedding time ≤ 1.2× bge-small; dist under SIZE_LIMIT 55,000,000 bytes (only one model bundled).
- Accept rule vs bge-small: ≥ +2 points on holdout2 and on sessions (both scenarios); no worse than −1 on holdout, holdout3, YouTube topics, messy YouTube; all quality gates pass.
- Public data: only British Library web_archive_classification (CC PDM) and Curlie (CC BY 3.0, attribution); subreddit-posts only as training supplement for niche labels; never AG News, Yahoo Answers, Amazon, Kaggle scrapes.
- New model id `tablight/bge-small-tabs-v1`; parity ONNX int8 vs PyTorch cosine ≥ 0.99 mean on 500 titles.
- Commits: separate -m flags, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never `git add -A`.

## Review Focus

1. Users upgrading with stored vectors from bge-small: every tab re-embeds and exemplars rebuild from lessons; nothing compares vectors across models (Task 6 test).
2. Offline load of the new model id (allowRemoteModels false, path `public/models/tablight/bge-small-tabs-v1/`) in the extension build (Task 6 e2e).
3. Threshold/similarity computed on rows the fine-tuned encoder trained on (inflated) — calibration split must exclude them (Task 3 test).
4. Benchmark leakage: no benchmark row text appears in any training file (Task 1 test).
5. Quantisation drift: int8 export degrades accuracy unseen in PyTorch numbers (Task 2 parity check).

### Task 1: Sealed benchmark

**Files:** Create `tests/benchmark/BRIEF.md`, `tests/benchmark/benchmark.json`, `tests/benchmark/SEAL.md`, `tests/benchmark/benchmark.test.ts`, `tests/unit/benchmark-seal.test.ts`.

- [ ] BRIEF.md: as training/SESSIONS.md (format, session shape, messy titles, 20–30% YouTube, ~10% other) with 20 new personas `b01`–`b20` unlike any in SESSIONS.md; 50–70 tabs each.
- [ ] Controller runs writers (fresh agents, one per 4 personas), then two independent labellers per row (label only, from LABELING.md, not seeing `group`), then an adjudicator for disagreements. Final `group` = agreed or adjudicated label. Record agreement rate.
- [ ] SEAL.md: row count, per-label counts, labeller agreement %, SHA-256 of benchmark.json, date. Nobody reads rows after this.
- [ ] `benchmark-seal.test.ts`: file hash equals SEAL.md's; no benchmark title or URL appears in any training/*.json or tests/quality/*.json (compare by normalized string, print counts only).
- [ ] `benchmark.test.ts`: `describe.skipIf(!process.env.BENCHMARK)`; prints precision (right / grouped), coverage (grouped / total), overall accuracy (right / total), per-label, with and without neighbours (sessions-sim style, auto-only), using loadProductModel.
- [ ] Commit `test: sealed accuracy benchmark` with the SHA in the message.

### Task 2: Fine-tune and export scripts

**Files:** Create `scripts/finetune/requirements.txt`, `scripts/finetune/finetune.py`, `scripts/finetune/export.py`, `scripts/finetune/README.md`.

**Interfaces:** Produces `finetune.py --pool training/ --out DIR --calib-share 0.2 --seed 1 [--extra FILE...]` → HF model dir + `DIR/calibration.json` (list of pool row keys held out); `export.py --model DIR --out MODELS_ROOT/tablight/bge-small-tabs-v1` → Xenova layout (`onnx/model_quantized.onnx`, config/tokenizer files) and prints mean/min parity cosine.

- [ ] finetune.py: stratified 80/20 split by label; text = `embedText` equivalent (port src/shared/url.ts embedText exactly; a test compares outputs on 200 rows via a JSON fixture generated from the TS function); training objective is the builder's call (contrastive pairs and/or MNRL with label descriptions), device mps; selects epochs by calibration-split kNN accuracy.
- [ ] export.py: optimum ONNX export, dynamic int8 (avx512_vnni-free, arm64-compatible config), copy tokenizer files; parity on 500 pool titles; exit non-zero if mean cosine < 0.99.
- [ ] README: venv setup with uv, commands, licence of base model (MIT).
- [ ] Commit `feat: fine-tuning and export scripts`.

### Task 3: Calibration split in train-head

- [ ] Env `CALIBRATION=path/to/calibration.json`: when set, the head is trained on all pool rows, but threshold, CV-style utility and similarity are computed only on calibration rows (out-of-fold over calibration rows only). Without it, behaviour is unchanged (existing tests stay green).
